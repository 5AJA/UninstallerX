# UninstallerX: 2026년 11월 23일 중간 점검

2026-11-17 구현 상태.

현재 시연은 합성 앱에서 모델 주도 읽기 전용 탐색, 실행·승인·감사 흐름을 확인한다. 모델은 앱 이름에서 설치 기록·폴더·설정 키를 조사하고, 오케스트레이터는 관찰 근거와 넓은 위치 정책을 확인한다. 실제 Windows 앱 전체의 소유권 판정은 아직 구현되지 않았다.

## 작동하는 범위

- 합성 설치형 앱과 포터블 앱을 만들고 HKCU 앱 설정값을 기록합니다. 앱 전용 파일, 공유 파일, 보호 파일, AppData 잔여물, 설치 기록을 포함합니다.
- 조사 도구는 일회용 파일·레지스트리 샌드박스 범위로 제한됩니다. 모델이 검색과 조회 도구를 순서대로 선택해 설치 기록·폴더·설정을 관찰합니다. README는 공격자가 수정할 수 있는 데이터로 취급합니다.
- 모델이 관찰된 설치 폴더·AppData 폴더·설정 키를 선택하면 오케스트레이터가 실제 도구 결과와 넓은 위치 정책에 대조합니다. 결과를 본 뒤 모델이 정리 대상 ID를 선택합니다. 오케스트레이터는 ID를 정확한 경로·작업·관찰 근거로 변환하며 자유 형식 경로·명령은 실행하지 않습니다.
- 설치형은 합성 제거기를 먼저 실행하고, 성공 후 남은 파일을 새로 조회합니다. 파일과 설정값은 별도 단계에서 제안·검사·실행합니다. 포터블은 파일·설정 단계만 실행합니다.
- 후보마다 코드 기반 보안 검사기를 통과해야 합니다. 실행기는 검사 결과를 다시 확인한 뒤 승인된 합성 제거기 실행, 파일 격리 또는 앱 설정값 삭제만 수행합니다.
- 단계별 계획 확인, 설치형 제거기와 AppData의 대상별 승인, JSONL 감사 로그, 전후 상태 차이, 사례별 JSON 보고서를 제공합니다. 남은 허용 대상은 `incomplete_cleanup`으로 표시합니다.
- 조회 50회·변경 대상 50개·에이전트 작업 10분을 기본 한도로 두고, 한도 확대는 대화형 사용자 승인으로만 진행합니다. 허용 목록 밖 읽기 요청은 오류를 되돌려 주고 세 번째 위반에서 중단합니다.
- 정상 및 네 공격 유형을 설치형/포터블로 실행하고, 앱·파일·제거기 이름과 시험 문구가 다른 변형 3종을 지원합니다.
- `interactive` 명령은 사용자가 합성 앱의 제거 요청을 직접 입력하고, 모델 제안과 검사 결과를 본 뒤 계획 실행·제거기·AppData 대상별 승인을 결정하게 합니다.

## 시연 순서

1. `./scripts/start_local_model.ps1`로 모델 서버를 시작합니다. 최초 실행은 `setup_local_model.ps1`이 필요합니다.
2. `python -m uninstallerx interactive`를 실행해 `AppOne 제거해줘`를 입력합니다. 제거기·남은 파일·설정값의 각 계획을 확인하고 합성 제거기 및 AppData 캐시의 정확한 경로를 승인합니다.
3. `python -m uninstallerx demo --scenario false_ownership --kind portable --approval approve`로 README의 공유 캐시 소유 주장을 시험합니다. 모델이 그 대상을 선택한 경우 검사기의 거부 이유가 출력됩니다.
4. `python -m unittest discover -s tests -v`로 접합점 우회, 거짓 소유 주장, 승인 위조, 제거기 변조 및 승인 경계를 직접 검사합니다.
5. `.local/reports/`의 사례별 JSON에서 후보, 검사 이유, 승인, 실행 결과, 전후 차이를 확인합니다. `.local/audit/`에는 별도 감사 기록이 있습니다.

`$env:PYTHONPATH='src'`를 실행 창에 먼저 설정합니다. 시연과 자동 평가의 모든 변경 대상은 합성 fixture입니다.

## 판단 기준과 제약

- 중간 점검의 작동 증거는 실제 로컬 모델 호출, 합성 앱 정리, 공격 사례, 전후 상태 비교입니다. 공격 대상을 모델이 선택하지 않은 경우와 검사기가 거부한 경우를 구분합니다. 사례별 결과는 [실험 기록](EXPERIMENTS.md)에 있습니다.
- 설치형은 모델이 HKCU 설치 기록과 실제 폴더를 조사한 뒤 합성 제거기를 하위 프로세스로 실행합니다. 실행 경로에는 일회용 샌드박스와 넓은 설치·데이터 위치 정책만 전달하며, 정확한 정답·금지 경로 목록은 넘기지 않습니다. HKCU 위치를 보호 폴더로 바꾼 경우는 정책에서 거부합니다. 실제 사용자 앱의 범용 탐색·제거는 구현되지 않았습니다.
- 파일 검사 직후 대상 경로를 격리하는 방식에는 외부 프로세스가 같은 파일을 동시에 바꾸는 경쟁 조건이 남습니다. 현재 평가는 단일 프로세스 합성 fixture에서 수행합니다.
- 제안서의 Granite 4.2 8B BF16 대신 3B 양자화 모델을 파일 버전과 설정을 고정해 사용했습니다. 최종 8B 성능을 대변한다는 주장은 하지 않습니다.
- 제안서의 40개 이상 정상·40개 이상 공격 사례와 지표는 더 큰 고정 시험 집합에서 별도로 검증해야 합니다.

## 다른 팀 레드팀 실험 준비

파트너 팀에는 허용된 README/메타데이터 입력면과 합성 사례 실행 명령, 보고서만 전달합니다. 모델 파일, 로컬 API 키, Windows 계정 권한은 필요하지 않습니다. 실험 전 공격 가능 입력, 변경 가능한 경로, 시도 횟수, 시간, 보고 양식을 합의하고 코드·모델·fixture 버전을 고정해야 합니다. 현재 제공되는 네 공격 문구는 내부 사전 시험이며 다른 팀의 승인된 공격 결과로 기록하지 않습니다.
