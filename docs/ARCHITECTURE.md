# UninstallerX 실행 구조 (11월 23일 중간 점검 범위)

합성 모드의 11월 23일 점검 구조와 실제 Windows 앱 모드를 설명한다.

## 실제 Windows 앱

1. 모델이 요청에서 앱 이름과 제거 의도를 파악한다. 필요하면 Windows 목록에서 조회할 앱 이름 표기를 제안한다.
2. 모델이 설치 기록, MSIX 패키지, 포터블 폴더 조회 중 다음 읽기 도구를 선택한다. 오케스트레이터는 선택된 도구만 실행하고 관찰 ID와 결과를 모델에 돌려준다. 모델이 결과에 나온 후보를 후속 조회하고, 관찰된 제거기 명령·패키지·포터블 파일 중 정확한 대상을 제안한다.
3. 보안 정책은 서명, Windows Installer 제품 코드, 현재 사용자 패키지 정보 또는 파일 경로와 해시 등을 다시 검사한다. 제안이 없거나 근거가 불충분하면 실행할 계획이 없다. 기본 UI는 읽기 전용이며, `--apply`에서 사용자에게 정확한 대상을 승인받은 후 실행한다.
4. Win32·MSI, MSIX·AppX, 포터블 앱의 제거가 확인되면 모델이 AppData와 사용자 Temp의 잔여 파일과 폴더를 조사한다. 모델이 제안한 경로를 별도로 승인받은 뒤 대상을 다시 검증하고 영구 삭제한다. Win32·MSI는 현재 사용자 제품 설정값도 별도로 조사하고 승인받는다. 설정 키 전체와 프로필은 유지한다. MSIX 패키지 자체의 데이터는 Windows가 처리한다.
5. 실제 모드는 조회 50회, 직접 변경 대상 50개, 10분으로 시작한다. 사용자가 숫자로 표시된 증가분을 승인하면 같은 조사 상태를 유지해서 진행한다. 확대를 거부하면 기존 한도를 초과하는 읽기나 변경을 진행하지 않는다. 모델 응답, 읽기, 승인, 한도 확대, 실행을 `.local/audit/windows-*.jsonl`에 남긴다.
6. 파일을 옮기거나 설정값을 제거하기 전에 인증된 로컬 복구 기록을 쓴다. 복구 기능은 해당 작업에서 승인한 원래 위치를 다시 보여주고, 승인 뒤 백업 무결성과 현재 상태를 확인한다. 기존 대상은 덮어쓰지 않는다. 벤더 제거기 자체 변경은 복구 대상에서 제외한다.

## 합성 모드

| 단계 | 현재 동작 | 신뢰 경계 |
|---|---|---|
| 사용자 요청 | 요청에서 앱 이름과 제거 의사를 확인한다. `--app-name`으로 임의 이름의 합성 앱을 만들 수 있다. | 사용자 요청은 앱 이름과 작업 의도를 정한다. 앱 제공 자료의 지시는 요청을 바꾸지 못한다. |
| 읽기 전용 탐색 | Granite 모델이 `search_uninstall`, `find_named_dirs`, `search_settings`, `list_dir`, `list_registry_values`를 순서대로 선택한다. 도구 결과에는 짧은 ID와 관찰 참조를 붙인다. | HKCU 설치 기록과 앱 파일은 단서다. 모델은 쓰기 도구에 접근할 수 없다. 도구는 일회용 파일·레지스트리 범위에서만 읽는다. |
| 앱 식별 | 모델이 관찰된 설치 폴더, AppData 폴더, 설정 키, 설치 기록을 선택한다. 오케스트레이터가 실제 관찰과 비교하고 앱 이름, 서로 다른 폴더, 넓은 설치·데이터 위치 정책을 검증한다. | 제안한 경로나 관찰 참조를 그대로 신뢰하지 않는다. 보호 폴더를 설치 위치로 바꾼 HKCU 기록은 위치 정책에서 거부한다. |
| 작업 제안 | 설치형은 제거기를 먼저 제안한다. 성공 뒤 모델이 남은 파일을 새로 조사하고, 설정값을 별도로 조사한다. 후보는 작업·정확한 대상·관찰 근거를 가진 정형 객체로 바뀐다. | 모델의 자유 형식 명령은 실행하지 않는다. 앱 제공 텍스트만으로는 소유권 근거가 되지 않는다. |
| 보안 검사와 승인 | 앱 식별, 관찰 근거, 경로·접합점, 중첩 파일, 제거기 해시·절대 경로 인자, 작업 한도를 검사한다. 대화형 모드에서 단계별 계획과 제거기·AppData의 정확한 대상을 승인받는다. | 후보는 실행 권한이 아니다. 실행 직전에 검사를 반복한다. |
| 실행과 기록 | 합성 벤더 제거기를 하위 프로세스로 실행하고, 허용된 잔여 파일을 격리하며 앱 설정값을 삭제한다. JSONL 감사 로그와 전후 상태 보고서를 남긴다. | 제거기가 실패하거나 거절되면 후속 정리를 진행하지 않는다. 감사 로그는 모델의 읽기 도구 범위 밖이다. |

fixture의 `allowed_changes`와 `attack_target`은 실행 **후** 채점에만 사용한다. 실행 경로에는 정확한 정답·금지 파일 목록을 넘기지 않는다. 설치·데이터 영역의 넓은 정책 경계는 시험 샌드박스 설정으로 전달한다. 이 경계는 개별 앱의 정답 경로가 아니다.

이 표의 합성 도구는 샌드박스와 시험용 HKCU 기록을 사용한다. 파일의 폴더명과 목록만으로 모든 소유권을 증명할 수 없어 중첩 파일은 보수적으로 거부한다. 독립 공격팀 시험과 대규모 고정 평가는 아직 없다.
